# three.js llms.txt — vendored and pinned

Source:  https://threejs.org/docs/llms.txt
Fetched: 2026-08-10
Pinned to the version this repo installs: three 0.185.1 / @types/three 0.185.4.

This is the *relevant part* of upstream's llms.txt, not a copy of it. Upstream is
written for someone pasting a single HTML file into a browser. This repo is a
bundled, pinned, npm-installed TypeScript project, and three of upstream's four
"instructions for LLMs" are wrong here. They are listed under DELIBERATELY
DROPPED at the bottom so you do not go and re-read them.

For actual signatures, read `docs/three-api.md` — it is generated from the
installed `@types/three`, so it cannot disagree with the compiler. For behaviours
that bite (readback orientation, colour management, WebGL context limits), read
`docs/three-0.185-notes.md`.

--------------------------------------------------------------------------------
APPLIES HERE
--------------------------------------------------------------------------------

Renderer choice
  WebGLRenderer  — default, mature, maximum compatibility. This repo uses it.
  WebGPURenderer — `import * as THREE from 'three/webgpu'`; requires
                   `await renderer.init()`. First-class in 0.185, but it is a
                   different entry point and a different capture path. Do not
                   switch to it as a side effect of another task.

TSL (Three.js Shading Language)
  For custom shaders under WebGPURenderer, `import { texture, uv, color } from
  'three/tsl'` and assign nodes (`material.colorNode = ...`) instead of writing
  GLSL strings or using `onBeforeCompile`. Node materials are the ones named
  *NodeMaterial: MeshBasicNodeMaterial, MeshStandardNodeMaterial,
  MeshPhysicalNodeMaterial, LineBasicNodeMaterial, SpriteNodeMaterial.
  NOT USED HERE: this game is unlit MeshBasicMaterial on an orthographic camera,
  which is what makes a pixel assertion mean something.

Addons live under `three/addons/...`
  Not `three/examples/jsm/...`. Both resolve in some builds; only the first is
  current.

The API surface upstream considers essential (all present in 0.185.1)
  Core         Object3D, BufferGeometry, BufferAttribute
  Scenes       Scene
  Cameras      PerspectiveCamera, OrthographicCamera
  Renderers    WebGLRenderer, WebGPURenderer
  Objects      Mesh, InstancedMesh, Group
  Materials    MeshBasicMaterial, MeshStandardMaterial, MeshPhysicalMaterial
  Geometries   BoxGeometry, SphereGeometry, PlaneGeometry
  Lights       AmbientLight, DirectionalLight, PointLight, SpotLight
  Loaders      TextureLoader, GLTFLoader
  Controls     OrbitControls, TransformControls   (both under three/addons/)
  Math         Vector2, Vector3, Matrix4, Quaternion, Color

--------------------------------------------------------------------------------
DELIBERATELY DROPPED (upstream says it; it is wrong for this repo)
--------------------------------------------------------------------------------

1. "Use import maps with a CDN URL."
   Upstream's headline instruction. This repo bundles with esbuild and imports
   bare `'three'`. An import map would not resolve, and adding one to
   `public/index.html` breaks `just run` and every render test.

2. "Always use the latest version."
   No. `three` is pinned to 0.185.1 and `@types/three` to 0.185.4 because
   `just verify` includes a golden image and three does not follow semver — the
   minor number IS the version, and a bump can change rasterised output.
   Upgrading three is an "ask first" change (see AGENTS.md).

3. The worked TSL / WebGPU snippets.
   Correct upstream, irrelevant here, and example code that does not match the
   surrounding project is exactly what pulls generated code toward APIs this
   template does not use. Signatures are in `docs/three-api.md` instead.

4. "three ships its own types."
   It does not. Types come from `@types/three`, versioned separately, and its
   version number does not track three's.
